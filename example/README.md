# Python 基础示例

在项目根目录运行，使用项目已有的 Python 环境：

```bash
uv run python example/01_rollout/main.py
uv run python example/02_single_shooting/main.py
uv run python example/03_shooting_gradients/main.py
uv run python example/04_mpc/main.py
uv run python example/05_point_constraints/main.py --plot
```

也可以将 `uv run python` 替换为 `.venv/bin/python`。所有示例都不需要图形界面或 C++ 构建。
第五例的 `--plot` 可选，启用后会保存 `output/examples/05_point_constraints.png`。

| 示例 | 主要问题 | 模型 |
| --- | --- | --- |
| 01_rollout | 给定控制会产生什么轨迹？ | 一维位置积分 |
| 02_single_shooting | 如何选择控制满足终点约束并降低代价？ | 一维位置积分 |
| 03_shooting_gradients | 控制改变如何影响未来状态和代价？ | 差速车辆 |
| 04_mpc | 执行一步之后如何重新规划？ | 一维位置积分 |
| 05_point_constraints | 如何把车身与障碍点的距离加入优化？ | 固定朝向的二维平移 |

各示例独立运行，模型按教学重点选择，并非逐步复制完整 C++ 规划器。

## 01：Rollout 是什么？

英文短语 **roll out** 有“展开、铺开”的意思，例如把卷着的东西展开。
**rollout** 是相应的名词写法；在控制和轨迹优化语境里，可以把它理解为
“把未来的状态一步一步展开计算”，常称为**前向模拟**或**轨迹展开**。
这里并不是软件发布语境中的“上线、推出”。代码里也常用 `rollout` 作为函数名。

它回答一个具体问题：**从当前位置出发，如果依次使用这些控制，会得到什么轨迹？**

需要三个要素：初始状态、运动模型、给定的控制序列。本例用速度控制一维位置：

```text
下一位置 = 当前位置 + 时间步长 × 当前速度
x[k+1]   = x[k]    + dt       × u[k]
```

从 `x[0] = 0 m` 出发，每步持续 `1 s`，依次施加 `[1, 2, 3] m/s`：

```text
x[0] = 0
  └─ u[0] = 1 → x[1] = 0 + 1 × 1 = 1
                   └─ u[1] = 2 → x[2] = 1 + 1 × 2 = 3
                                    └─ u[2] = 3 → x[3] = 3 + 1 × 3 = 6
```

得到轨迹 `[0, 1, 3, 6]`。注意：**3 个控制产生 4 个状态**，因为轨迹包含初始状态。
每一步都使用上一步算出的状态；对于一般模型，就是反复计算 `x[k+1] = f(x[k], u[k])`。
本例的状态只是位置，项目中车辆的状态则包含位置和朝向，展开过程的思想相同。

可以把 rollout 想成“先在模型中试走一遍”。它本身不要求执行真实动作，也不保证到达目标；
预测是否准确取决于运动模型。这个示例中的整段控制是预先给定的，在其他语境里也可以由策略逐步生成控制。

试着修改 `DT`、`X_INITIAL` 或控制序列，先手算再运行。例如将 `DT` 改成 `0.5`，
第一组控制会得到 `[0, 0.5, 1.5, 3]`。

## 02：从 Rollout 到 Single Shooting

第一例对比两组预先给定的控制：

| 控制序列 | 预测轨迹 | 控制平方和 |
| --- | --- | --- |
| `[1, 2, 3]` | `[0, 1, 3, 6]` | 14 |
| `[2, 2, 2]` | `[0, 2, 4, 6]` | 12 |

它们都到达位置 6，但第二组控制的平方和更小。第二例让优化器自动寻找这样的控制：

```text
最小化：J(U) = Σ u[k]²
满足：  x[k+1] = x[k] + DT × u[k]
        x[0] = 0，x[N] = 6
```

这里的代价是教学用的控制平方和，不直接等同于真实车辆的能耗。

**Single shooting（单次打靶）的关键是：只把控制序列 U 作为决策变量，
状态轨迹 X 由 rollout(U) 计算得到。** 运动学通过展开自动满足，终点约束交给优化器处理。

```text
优化器提出一组 U
    → rollout 从固定初始状态展开整段 X(U)
    → 评价代价和终点约束
    → 优化器调整 U，并重复求解过程
```

“Single”不表示优化器只迭代一次，而是指每条候选轨迹都从一个初始状态连续展开整个时域。
本例代价直接依赖 U，终点约束通过 rollout 依赖 U；更一般的跟踪代价也会依赖 X(U)。

第二例还同时计算状态雅可比 `S[h, j] = ∂x[h] / ∂U[j]`，表示
“第 j 个控制改变一点，第 h 个状态会改变多少”。这不是 rollout 的必要输出，
而是为了向优化器提供解析导数而额外传播的信息。第一次阅读可以先看状态更新，之后再读雅可比部分。

在 `DT = 1` 时，雅可比为：

```text
         u[0]  u[1]  u[2]
x[0]       0     0     0
x[1]       1     0     0
x[2]       1     1     0
x[3]       1     1     1
```

初始状态固定，不受控制影响；未来的控制不影响过去的状态，所以矩阵呈阶梯形。
代码中的 `A_h` 是单步模型对当前状态的导数，`B_h` 是对当前控制的导数，
`E_h` 是在第 h 个位置为 1、其余位置为 0 的行向量，用来选择当前控制。

本例终点约束要求 `u[0] + u[1] + u[2] = 6`。在和固定时，三个控制相等使平方和最小，
所以最优控制为 `[2, 2, 2]`，代价为 12，可以用来核对求解结果。

对应 C++ 实现可阅读 `src/mppc.cpp` 中 `ShootingProblem::rollout()`：它将状态展开
扩展到车辆的位置、朝向，并传播状态对整段控制序列的导数。MPC 则在此基础上反复求解，
每次只执行第一个控制，再从新的观测状态重新规划。

## 03：状态灵敏度与梯度检查

本例改用项目中的差速前向 Euler 模型，状态为 `(x, y, yaw)`，控制为 `(v, omega)`：

```text
x_next   = x   + dt * v * cos(yaw)
y_next   = y   + dt * v * sin(yaw)
yaw_next = yaw + dt * omega
```

控制展平顺序是 `[v0, omega0, v1, omega1, ...]`。`S[k]` 是一个 `3 × 2N` 矩阵，
包含第 k 个状态对所有控制分量的导数。先计算单步模型的 `A = df/dstate`、
`B = df/dcontrol`，再用链式法则传播：`S[k+1] = A @ S[k]`，并在当前控制对应的两列加上 B。

位置误差平方和通过 `S` 对控制求导，控制平方惩罚则直接求导。代码中的 `einsum`
将各预测时刻、各位置分量的“误差 × 状态导数”求和，得到每个控制分量的梯度。

为了检查解析推导，另外逐个扰动控制，并计算中心差分：

```text
df/dU[j] ≈ (f(U + epsilon * e[j]) - f(U - epsilon * e[j])) / (2 * epsilon)
```

程序检查整段状态雅可比和标量目标梯度，分别使用 `1e-3`、`1e-5`、`1e-7` 三种扰动尺度。
误差超过容差会触发异常。epsilon 过大存在截断误差，过小会受到浮点舍入影响，并非越小越好。
这是在给定非零朝向、转弯控制上的数值检查，不是所有输入下正确性的数学证明。

可尝试修改控制序列，观察早期转向控制如何影响后续位置。
对应 C++：`ShootingProblem::rollout()` 的雅可比递推与 `objective()` 的链式求导。

## 04：滚动时域控制 MPC

本例回到一维模型，以突出闭环流程。每轮优化未来 8 步的位置误差和控制平方和，
末端位置误差权重更大，速度限制为 `[-2, 2] m/s`。终点是代价中的软目标，
不要求每个短预测时域内都精确到达，否则远离目标时可能因速度限制而不可行。

每一轮的顺序是：

1. 读取当前状态，求解整段控制序列。
2. 只执行第一项控制，并获取更新后的状态。
3. 将剩余控制左移，末尾重复最后一项，作为下一轮的初始猜测。
4. 从新状态重新优化，直到接近目标并接近静止。

第 6 轮执行后，示例人为施加 `-0.8 m` 的位置扰动。输出中的原预测位置与实际位置因此不同；
下一轮会从新的实际位置重新规划。热启动只是初始猜测，优化器仍会重新求解。
本例没有加速度约束或传感器噪声，重点是“预测—执行首项—观测—重算”的循环。

可尝试修改预测步数 N、控制惩罚或扰动大小，观察接近目标的过程。
对应 C++：`MppcPlanner::solve()` 的热启动，以及 `src/simulation.cpp` 的闭环执行。

## 05：点到矩形车身的距离约束

本例将控制改为世界坐标中的 `(vx, vy)`，矩形车身朝向固定为 0.2 rad。
它可以横向平移，不具备差速车的非完整约束，目的是单独讲清几何距离和约束构造。

对每个预测车身中心，将障碍点转换到车体系：`p_local = R.T @ (point - center)`。
设矩形半尺寸为 `half_size`，计算：

```text
q = abs(p_local) - half_size
d = norm(max(q, 0)) + min(max(q_x, q_y), 0)
```

车身外部的 d 是点到矩形的欧氏距离，边界为零，内部为负值。
负值扩展让进入车身的点也能产生约束违反量。棱角和部分内部位置不可微，
本例在约束字典中通过 `"jac"` 提供距离约束和终点约束的解析雅可比，
目标代价仍使用求解器数值差分。距离导数由“距离对中心的导数 × 中心对控制的导数”得到。
在内部最近面并列、矩形角点等不可微位置，选用一个分支的极限梯度，
没有声称处处存在唯一梯度。可独立运行以下检查，在可微位置与中心差分比较：

```bash
uv run python example/05_point_constraints/check_jacobians.py
```

优化中要求每个点、每个采样位姿都满足 `d - safety - margin >= 0`。
注意 SciPy 的 `ineq` 使用大于等于零，而 C++ NLopt 的不等式约定为小于等于零。
目标是接近起终点之间的直线，同时惩罚控制平方和；末端位置采用等式约束。

优化每个区间检查 4 个位姿，另外检查初始位姿；结果用每区间 20 个位姿复核基本安全距离，
同时检查终点误差和控制边界。默认安全距离为 0.2 m，优化时额外加入 0.03 m 采样余量。
这些约束只针对给定障碍点，不能代表点之间也存在障碍物，更不能证明连续时间绝对无碰撞。

绕障问题非凸，示例使用向上拱起的轨迹作为初始猜测，选择从上方绕行，不保证全局最优。
可以把初始轨迹的正弦项改为负值观察另一侧绕行，也可以修改 `YAW`、`HALF_SIZE` 或障碍点。
启用 `--plot` 后，图中显示初始猜测、优化轨迹、障碍点以及沿途矩形车身。

对应 C++：`src/geometry.cpp` 中的点到矩形距离，以及 `ShootingProblem::constraints()`
中的逐点、逐采样位姿距离约束。完整 C++ 实现还包含变化的朝向、解析导数及更多工程约束。
